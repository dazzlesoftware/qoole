# Native asset discovery and references

`Runtime/AssetCore` now includes a synchronous asset registry, shared by all
four editor Content Browsers. It has no Editor, world-model, UI or RHI dependency.

The editor mounts project Content at `/Game`, Engine Content at `/Engine`, and
the user prefab folder at `/UserPrefabs`. Future plugin content can use another
root through the same mount API. Mount roots are unique, directories must not
overlap, and scans do not recurse through symbolic links. Package paths omit the
extension and use forward slashes, for example `/Game/Buildings/House`.

Scans read `.asset` and `.gmap` manifests only. They collect the package UUID,
kind, schema/version, logical and physical paths, dependency paths, and declared
payload sizes. They do not load exports, heightfields, textures, or instances.
`FAssetPackageStore::ReadMetadata` checks the manifest and sidecar declarations;
full `Load` checks actual sidecar data and checksums. An indexed package is not
a certification that its payloads are intact.

## Runtime API

```cpp
FAssetRegistry Registry;
FString Error;
Registry.SetMounts({ { "/Game", ContentDirectory } }, Error);
Registry.Scan();
const FAssetData* Asset = Registry.FindByPath("/Game/Buildings/House");
if (Asset)
{
    FAssetReference Reference = Asset->GetReference();
    FAssetPackage Package;
    Registry.Load(Reference, Package, Error, "Genesis.Prefab");
}
```

Check return values in application code. Invalid mount changes preserve the
existing snapshot. A scan replaces the snapshot and returns false if there are
issues, while retaining other discovered packages. `GetIssues()` describes
malformed manifests, incomplete scans and duplicate UUIDs/logical paths.
Pointers into a snapshot expire on the next successful SetMounts or any Scan.

References serialize as a JSON object with `Id` and `Path`. UUIDs are canonical
lowercase strings generated by `FAssetId::New`. An empty reference represents
no asset. A path-only reference is also supported.

When Id is present it is authoritative: a moved package with the same identity
can resolve after a rescan even if the path hint is old. A missing or duplicated
Id never falls back to another package at the hinted path. Path-only resolution
rejects ambiguous paths and packages with duplicated UUIDs. Explicit UUIDs can
distinguish different packages sharing an ambiguous logical name. Optional
schema checks keep a material reference from loading a prefab. Load verifies
identity again after reading the package, detecting replacement since discovery.

Lookups fold ASCII case, as does the existing FString case conversion. Unicode
names are retained; this is not full Unicode case folding.

## Editor behavior

- Native tiles are classified by schema/version and package kind. Supported
  world and prefab packages open/place as before. Unknown schemas appear as
  generic Asset tiles and are not assumed to be prefabs.
- Malformed or conflicting packages show a Content Issue tile with a diagnostic
  tooltip and cannot activate or drag as a prefab. The footer counts mount-wide
  issues and refresh writes diagnostics to the Output Log.
- Refresh rescans mounted content and updates all open browsers. Successful
  level/prefab saves and Content Browser imports refresh discovery too.
- Native prefab drag/drop carries an identity reference. Placement resolves it
  through the current registry and verifies that the loaded package still has
  the expected UUID. Older QLE placement remains path based.
- Updating an existing supported prefab retains its UUID. Importing a copy
  creates a new UUID. Saving a prefab cannot overwrite a different asset schema.

Refresh is explicit; no background filesystem watcher or persistent registry
cache is installed. Native package moves must rewrite/carry the complete package,
not rename its manifest alone. The registry resolves identities after such a
move; a package-aware rename/move editor UI is still pending.

## Remaining migration

This does not yet add actor/component UUIDs, a runtime World model, live prefab
instance links, persisted material/mesh references on actors, dependency fixups,
mesh/texture/material serializers or asset editors. Prefab placement still
creates an editable snapshot in the legacy document. Existing package dependency
lists remain logical paths; `FAssetReference` is the new identity-reference API
for subsequent serializers. Plugin loading and registration follow later.
